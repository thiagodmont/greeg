# W01a: exact search defaults

Date: 2026-09-22. Base: `1acde07fa` (`origin/main`). This PR implements the
matching-policy portion of W01 and starts W08's measurement discipline.
W01b remains a separate PR for hook capability/refusal rules and host protocols.

## Behavior and accuracy

Before: `greeg -l LOAD_CONFIG` printed paths containing only `load_config`
and exited 1. A downstream pipe could consume the incorrect paths anyway.
After: default file/count/unlimited output stays empty and exits 1; JSON
contains only no-match metadata. Ranked text still offers discovery, and
`--matching discover` explicitly restores it in machine formats.

The new CLI regression failed against the base binary before implementation.
The completed tests cover scan and full index, every machine-mode alias,
case/word/split/fuzzy misses, JSON metadata, explicit policy, the retained
`--no-ladder`, rejected conflicts, requested `-i`/`-S`/`-w` semantics, stdin,
and output-write failure. Existing phase-1/delta tests now check both exact
misses and explicitly enabled discovery; their former discovery assertions
were retained. All existing ranked-output tests still pass.

All **16 machine-text workload/backend combinations** matched ripgrep's
stdout and status. The baseline matched 10/16; six incorrect suggestion
streams were removed. This is a deterministic fixture result, not a claim of
general ripgrep compatibility. JSON semantics are covered by Rust tests,
not this text parity benchmark.

## Performance and token evidence

Protocol: release binaries, same Cargo.lock, Rust 1.94.0
(`4a4ef493e`, LLVM 21.1.8), aarch64-apple-darwin, macOS 26.5, 12 logical CPUs.
CPU model was unavailable in the sandbox. Python 3.13.6, ripgrep 15.2.0,
tiktoken 0.12.0 with `o200k_base`. The generated corpus has 256 Rust files,
1,287,368 bytes; its digest and both binary digests are in the raw artifacts.
The base version is `0.6.0+1acde07fa`; candidate is the same base plus this
PR's production edits (`0.6.0+1acde07fa.dirty`). Later edits only added tests,
comments, documentation, and tightened the benchmark's index-path assertion.

Each binary gets its own private temporary index and configuration directories.
Sessions/statistics are disabled; freshness is `stat`; queries use one reader
thread. Every case has three warmups and 31 paired observations, with randomized
binary order. Times include process startup. Compilation and tests were not
running during measurement. Public tokenizer data was cached before the run.

| Workload | Scan median, before → after | Indexed median, before → after | Output tokens, before → after |
|---|---|---|---|
| Case miss, files | 10.756 → 7.019 ms (−34.7%) | 7.720 → 6.906 ms (−10.5%) | 68 → 3, both backends |
| Word miss, count | 10.724 → 7.096 ms (−33.8%) | 7.720 → 6.921 ms (−10.3%) | 84 → 3, both backends |
| Split-name miss, unlimited | 13.219 → 7.183 ms (−45.7%) | 9.013 → 7.022 ms (−22.1%) | Scan 3 → 3; index 310 → 3 |
| Fuzzy-name miss, unlimited | 13.435 → 7.525 ms (−44.0%) | 10.825 → 6.451 ms (−40.4%) | Scan 3 → 3; index 309 → 3 |
| Absent identifier, files | 12.394 → 6.980 ms (−43.7%) | 11.198 → 6.612 ms (−41.0%) | 3 → 3, both backends |

Successful file/count/unlimited queries kept identical stdout and status;
median changes ranged from −0.8% to +0.6%. Their token counts were unchanged.
Tokens count stdout plus stderr, including diagnostic footers. Removing
incorrect suggestions is a correctness improvement; these figures do not
estimate whole-agent-task token savings.

Ranked hit/discovery stdout and status also stayed identical. The first
31-pair run showed a +39.0% scan-ranked-hit p95 difference despite a −0.2%
median, triggering the planned >20% tail investigation. A **151-pair recheck**
of both ranked cases found:

| Case | Median change | p95 before → after | p95 change |
|---|---|---|---|
| Scan ranked hit | −2.2% | 10.967 → 11.898 ms | +8.5% |
| Scan ranked discovery | +0.0% | 13.963 → 13.036 ms | −6.6% |
| Index ranked hit | +0.9% | 7.844 → 7.837 ms | −0.1% |
| Index ranked discovery | +0.2% | 8.646 → 8.957 ms | +3.6% |

No persistent regression above the investigation thresholds was observed on
this host. Both runs are retained; the rerun does not erase the original
outlier or establish equivalence on other machines. Binary size grew from
16,982,688 to 17,001,056 bytes (+18,368 bytes, approximately 0.11%).
Single index-build timings in the artifacts are setup observations, not
paired build-performance evidence.

## Verification and three-lens review

- `cargo test --workspace --locked --quiet`: **188 passed, 3 ignored**.
  The ignored tests are existing parser/tree dump diagnostics.
- `cargo fmt --all --check`: passed.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: passed.
- Locked release build, Python harness execution and `git diff --check`: passed.
- No dependency or lockfile changes. No production cache format changes.

**Correctness, edge cases and scope:** reviewed policy precedence, legacy
conflicts, explicit discovery, all output defaults, error exits and stdin.
Exact is independent of case sensitivity and display truncation. Added a
deterministic closed-reader test so an exact hit cannot mask an output failure.
Removed a potential race in the stdin refusal test: it need not write bytes
to a process that can reject its flags before reading. Known selection/cap/
classification defects remain W03 rather than being implied solved here.

**Architecture and maintainability:** one small `MatchingPolicy` replaces
the ladder boolean. The CLI resolves defaults once; query code enforces them
before fallback work, and rendering reports the selected behavior. Existing
symbol helper calls explicitly retain their old no-relaxation choices. No new
crate, dependency, query framework or index migration. Library callers must
replace `Options::ladder` with `Options::matching`; the documented default is
now exact. This is an intentional source-API/default change.

**Security, performance, compatibility and delivery:** the fix eliminates
unrequested relaxed stdout in machine modes. Explicit discovery remains an
opt-in that can emit suggestions with exit 1. Hook translation is not certified
by this PR. Measurement creates only owned disposable fixtures and never
checks out or cleans the caller's repository; no shell replay or model API is
used. Strengthened the benchmark probe to require `index` exactly, excluding
`index+scan` fallback. The p95 outlier was investigated and retained. Migration
is documented in [MATCHING.md](../MATCHING.md); no hooks are reinstalled.

Review coverage: 14 files total (9 previously tracked edits and 5 additions),
including all production changes, tests, docs, the harness and both JSON
artifacts. At review time there were no committed branch changes or staged
changes; all work was in the unstaged/untracked buckets. Raw JSON samples were
validated and their aggregates recomputed rather than reviewed line by line.
No unresolved blocking finding remained after these fixes.

Not run locally: Linux, MSRV 1.90, release archives, cold-cache/RSS/concurrency
benchmarks, FSEvents stress, large real corpora or paid agent-task evaluations.
The existing Linux PR workflow supplies an additional correctness gate; merge
requires reviewing its outcome. These local results do not complete W08 or
claim that the full reliability milestone is finished.
